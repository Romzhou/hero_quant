### 1.1 磁盘约束（必须先看）

`df -h` 显示根分区 49G 已用 47G，**可用 1.8G**（2026-10-28 清理后）。这直接改写了操作方式：

| 禁止 | 替代做法 |
|---|---|
| 拉 `postgres:16` 镜像（300M+） | 复用 `llm-pg`，或在 profile 里用本地已有的 `16-alpine` |
| 再起一套 postgres+redis（卷+镜像双写） | 直接用 `llm-pg` / `llm-redis` |
| 反复 `docker build`（每次 840M 镜像 + 缓存） | 先 `docker builder prune -f`（可回收 2.1G），构建一次即止 |
| 保留审计残留镜像 | `docker rmi hqaudit-hero-quant:test`（840M，是本项目审计时构建的，可安全删） |

**已执行（2026-10-28）**

```bash
docker rmi hqaudit-hero-quant:test      # 已删；可用 1.3G → 1.8G
```

实测释放约 0.5G，低于镜像标称的 840M —— 大部分层与无标签基础镜像（`python:<none>` / `node:<none>`）共享，真正可回收的只有本镜像独有的 186MB。

**暂缓：`docker builder prune -f`**

它能再回收 2.1G，但会丢掉 pip / npm 那几层缓存，下次 build 要重新下载依赖。**正确顺序：先让 S1 用缓存构建成功 → 再 prune**。

```bash
# 仅在构建报 no space left on device 时执行
docker builder prune -f
df -h /
```

基础镜像不会因此丢失：`python:3.11-slim` 与 `node:22-slim` 以无标签形式存在（ID 分别对应 Dockerfile 里的 digest `e031123e3d85` / `6c74791e557c`），重建不需重拉 600M。

## 2. 修复路线

```
S1 部署/依赖 ──► S2 后端主链 ──┐
（唯一前置）     S3 数据/回测 ──┼──► S5 测试门禁 ──► S7 文档对账
                 S4 计费      ──┘    S6 前端
```

| 批次 | 会话 | 能否并行 | 前置条件 |
|---|---|---|---|
| 批 0 | **S1** | 单开，必须先完成 | 无 |
| 批 1 | **S2 / S3 / S4** | 三路并行 | S1 完成（PG/Redis 能起，镜像能 build） |

**如果只想先让它「能起来」**：只开 S1，做完就能 docker compose config 通过 + 连上 llm-pg/llm-redis + uvicorn 跑通；P0-3 到 P0-8 仍在，但至少不是「连启动都不行」。

```text

依据：docs/audit-2026-10-28.md §3 第 6 层。python 用 .venv/bin/python。

现状两个 bug：
1) __init__ 从不建池（:246-260），_pool 恒 None，永远走内存 emulated；日志写 "PG persistence not implemented, using emulated store"（:212）却仍 publish/purchase 成功并返回 purchase_id —— 假成功。
2) 手动注入真池后，:526 的 SET LOCAL app.tenant = %s 是非法参数化语法，事务 abort，publish 抛 RuntimeError。

修：
 - __init__ 读 HERO_BILLING_DSN（经 settings 网关，不要绕过去直接读 os.environ），有 DSN 就建 psycopg_pool 连接池并 SELECT 1 探活；探活失败 fail-closed。

 - 无 DSN / 池不可用：publish / purchase 返回明确失败（异常或 {"ok":False,"error":"billing_unavailable"}），禁止返回成功或生成 purchase_id；API 层转 503。
```

## 7. 已知坑（开工前看一遍）

1. **PG/Redis 地址**：复用 `llm-pg` / `llm-redis`，只绑在 **100.114.54.26**（tailscale），`127.0.0.1:5432/6379` 是 refused。DSN 一律写 100.114.54.26，写 localhost 必连不上。
2. **PG 超级用户名不是 postgres**：`psql -U postgres` 会报 `role "postgres" does not exist`。用容器内 `$POSTGRES_USER`：`docker exec llm-pg sh -c 'psql -U "$POSTGRES_USER" -lqt'`。
3. **heroquant 库还没建**：llm-pg 里只有 `llm_backend` / `postgres` / `template*`，S1 必须先 `CREATE DATABASE heroquant` 再跑 DDL。
4. **磁盘只剩 1.8G**：禁止拉 `postgres:16`（300M+）、禁止起第二套 stack、禁止反复 build。审计残留镜像已删；构建缓存 2.1G 留到 S1 构建成功后再 prune，中途 ENOSPC 才提前清。
5. **没有 psql / redis-cli**：验证一律 docker exec，不要在宿主机装客户端。
6. **migrations/ 冻结**：DDL 只能复制到 scripts/init/，改原件会被打回。
7. **S2 行号会变**：S2 改完后审计文档里 server.py 的行号全部失效，S7 必须重新 grep。
8. **测试数会变**：S5 会增删用例，README 数字以 S5 完成后的实测为准。
9. **不 push**：出网受限，push 会卡在凭据提示；所有产出留在本地 master。
10. **别 down -v**：`docker compose down -v` 只删本项目的卷，但如果你误对 `llm-pg` 执行删除，会连带 `llm_backend` 库一起没。
