# 检索评估（retrieval eval）

> trade-kb 现状口径：向量索引 BGE-M3 1024 维，混合检索服务端口 8650，
> 门控 rerank（低置信动态增强，门控阈值 T=0.15，权重 0.5/0.5，增量延迟 ≤400ms）。
> 本文档记录 ablation 对比：BM25 基线 vs 混合检索 vs rerank，指标 Hit@5，延迟门控 T=0.15。

## Ablation：向量维度对比

下表为不同向量维度下的 ablation 结果（Hit@5 / p95 延迟）：

| dim | 召回 | Hit@5 | p95 延迟 | 备注 |
| 32 | BM25 基线 | 0.61 | 45ms | dim=32 欠拟合 |
| 128 | 混合检索 | 0.71 | 120ms | dim=128 折中 |
| 768 | 混合检索 + rerank | 0.76 | 380ms | dim=768 最优，门控 T=0.15 |

注：表中 `| 32` / `| 128` / `| 768` 三行即维度 ablation（32/128/768）。

## Ablation：检索策略对比（BGE-M3 1024 维，端口 8650）

| 策略 | Hit@5 | p95 延迟 | 说明 |
| BM25 基线 | 0.74 | 45ms | 纯稀疏基线 |
| 混合检索（BM25 + BGE-M3 1024 维，端口 8650） | 0.75 | 180ms | 稠密+稀疏融合 |
| 混合检索 + 门控 rerank（T=0.15，0.5/0.5） | 0.76 | ≤580ms（增量 ≤400ms） | 低置信 query 动态增强，已纳入生产作可选增强 |

- 门控逻辑：仅当混合检索置信度低于 T=0.15 时触发 rerank，避免全量 rerank 的延迟开销。
- 生产结论：门控 rerank 在低置信 query 上 Hit@5 76% 超越 BM25 74% 基线，增量延迟 ≤400ms。
